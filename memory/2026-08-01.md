### ⚠️ THE BIG ONE — Stripe webhook CI failures (16 tests)
After `9ee4c9f`, CI shard 4 failed with 16 failures in `test_stripe_webhook_lifecycle.py` (KeyError 'action', status asserts, DID NOT RAISE). All 20 tests passed locally in isolation.

**Root cause (finally):** `test_stripe_webhook_idempotency.py::test_concurrent_distinct_events_create_multiple_records` applies `patch.object(StripeSubscriptionService, 'verify_signature'/'_tenant_from_event')` **inside each thread**. The threads race on enter/exit of the mock patches; a thread can exit while another is mid-ingest, and the stack-based restore logic leaves **MagicMock leftovers permanently on the class attributes**. Every subsequent test in the process sees `_tenant_from_event` = mock → returns None → tenant_not_found → `{'ignored': True}` → KeyError 'action'; `verify_signature` mock → returns stale event dict → missing_event_id/invalid_payload tests DID NOT RAISE.

**Diagnosis path:** git log showed `280d268` (last green) → all our commits red; but even old tenant_context.py reproduced → not my change. Reproduced locally: `test_stripe_webhook_idempotency.py` + `test_stripe_webhook_lifecycle.py` on local Postgres (`TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/medical_test`) → 16 failed, identical list. Isolated: single idempotency test + lifecycle test → only the THREADED one poisons (deterministic in-pair). Diag test in same file passed — poison only visible in NEXT test's context. Instrumented `_tenant_from_event` with prints → zero DIAG lines from lifecycle tests → the function never ran → leftover mock. Confirmed with a check test: `isinstance(cls._tenant_from_event, MagicMock) is True`.

**Fix:** moved both `patch.object(...)` calls OUTSIDE the thread bodies (patch once before `Thread.start()`, restore after `join()`); `verify_signature` side_effect `lambda p, s: json.loads(p)` (classmethod → 2 args, NOT 3). Verified: idempotency+lifecycle+subscription_webhook = 29 passed; pair ×3 stable; POS test still passes. Pushed `9598190`.

### Lessons learned (IMPORTANT)
1. **Never patch class methods inside threads** — mock enter/exit is not thread-safe; leftovers corrupt the whole process.
2. pytest `--tb=line` HIDES captured stderr — DIAG prints invisible; use `--tb=short/long` or `-s`.
3. When a file passes in isolation but fails in the suite: reproduce with the PRECEDING test files (shard order), not the file alone.
4. pytest-split without durations file = deterministic even split by nodeid order → same shard content between commits.
5. Don't jump to blaming the last code change — I wrongly suspected my own tenant_context.py ACTIVE change (it was innocent) until I tested with the OLD file version.
