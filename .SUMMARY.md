## Key Decisions
- Use `g.enabled_modules` for inter-module checks in route handlers rather than calling `guard_module('lab')` or `guard_module('radiology')` because those routes live on `doctor_bp` (guarded by `'doctor'` module) — adding a second `guard_module()` call inside the route would conflict with the blueprint-level guard.
- `first_or_404()` chosen over manual `flash + redirect` for patient/visit lookups because it guarantees an immediate abort without falling through to subsequent tenant-sensitive queries — eliminates race windows between the lookup and the first tenant-scoped query.
- `PermissionError` in service layer instead of silent skip because downstream route handlers inspect the return value; a silent skip could be mistaken for successful creation.
- Template gating applied to the container/card/tab level rather than each individual button — fewer lines changed, same security posture, easier to audit.

## Critical Context
- `AutoTenantFilter` in `app/shared/tenant_filter.py:99-139` injects `WHERE tenant_id = :tenant_id` into all `Query.before_compile` events — but `db.session.get(Model, id)` does NOT go through `Query.before_compile`, making it a documented bypass vector.
- `doctor_bp` is registered with `_add_guard_once(doctor_bp, "doctor")` in `app_factory.py:609` — only the `"doctor"` module is required to access any route on this blueprint.
- `get_active_modules_for_tenant()` in `app/core/module/validators.py:47-76` reads from `TenantModule.is_active` — this is the source of truth for `g.enabled_modules`.
- `guard_module('doctor')` at `routes/doctor/__init__.py:34` is a `before_request` hook — it runs before every doctor route. Nested `guard_module('lab')` inside a doctor route would fail because `'lab'` is not the blueprint's module — so we must read `g.enabled_modules` directly.
- `is_entitled('pos_terminal')` is used in `pharmacy/pos.html:64` — this is a different gating mechanism (capability-based, not module-based).
- Template-level `module_active('billing')` already demonstrated in reception/manager templates from previous session — same pattern applied for `module_active('lab')` / `module_active('radiology')`.
